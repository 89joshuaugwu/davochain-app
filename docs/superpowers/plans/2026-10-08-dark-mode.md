# Davochain Dark Mode Implementation Plan

> For agentic workers: use superpowers:executing-plans; parallelize independent feature migrations with disjoint ownership. User automatically approved design, plan and inline execution on 8 October 2026.

**Goal:** Persist Light/Dark/System appearance and render the existing app readably in each mode.

**Architecture:** Context-resolved DavoColors ThemeExtension and Material themes; AppearanceController with async preferences; intentionally light receipt subtree. Keep existing immutable brand constants.

**Tech stack:** Flutter, SharedPreferencesAsync, existing Sora and vector motion.

**Spec:** ../specs/2026-10-08-dark-mode-design.md

## Global constraints

No font-size increases, no financial flow changes, no global color inversion, preserve splash and multicolor art, no automatic commits. Base palette as specified in design. Preference save failures cannot silently apply. Receipt exports remain white.

## Review focus

System changes while a nested modal is open; explicit mode differing from OS; back cancels unsaved appearance; save failure retains old preference; nested receipt theme never inherits dark ink/surface; status bars and keyboard agree with surface; fixed raster monochrome icons remain visible.
