# Security questions

User intent: exactly three distinct preset/custom questions, answers entered sequentially; previously chosen questions disabled; challenge after returning login (PIN/fingerprint/password), before Home; changing questions requires email-code verification. Preserve blue/Sora/light/dark/reduced motion and existing success artwork. Prior automatic implementation authorization remains applicable; no repeated approval gates or commits.

This is an additional knowledge check, not true MFA. All verification is explicitly session-only preview until authenticated server endpoints exist; no credentials/answers/OTP in disk storage or logs. Email code is a displayed preview fixture, never represented as delivered email. No transaction authorization prompts changed.

Model `lib/features/security_questions/security_questions_service.dart`: QuestionAnswer(question,answer); SecurityQuestionsService extends ChangeNotifier, session singleton `instance`, constructor injectable DateTime Function()? now. Public questions List<String>, enabled bool, saveInitial(List<QuestionAnswer>), verifyAnswers(List<String>) async bool, requestReset() async ResetChallenge, confirmReset(challengeId,code) async String grant, replaceQuestions(grant,List<QuestionAnswer>) async. ResetChallenge(id,previewCode,expiresAt). clear() for account deletion/other-account, invalidateReset() on canceled reset. Inputs exactly3, unique normalized questions, meaningful nonempty answers, no duplicates custom/default. Matching answers trim/collapse spaces/case-insensitive, preserve punctuation. Preview answers salted hashes in RAM using crypto; no raw answer getters. Five failed attempts trigger temporary lock with injectable clock; reset code expires5min, max5attempts, single-use grants expires5min and generation-bound. Replacement atomic; canceled/error reset leaves old set intact. Initial setup cannot overwrite an enabled set.

UI `presentation/security_questions_screens.dart`: SecurityQuestionsSettingsScreen({service?}), setup wizard exactly3steps allowing edit/back, question picker showing selected unavailable presets + custom option, obscured answers visibility control, review containing questions only, explicit save and result; email code reset screen; login challenge all3 answers obscured, no hints, no Home bypass, cancellation returns to primary unlock; recovery email reset replaces questions but does not unlock Home directly. Public SecurityQuestionsChallengeScreen({service?,required VoidCallback onVerified,VoidCallback? onCancel}). Setup accessible via Settings security section. Default questions about favorite teacher, first concert, childhood nickname, memorable place, first book, childhood ambition; encourage memorable private answers and no passwords/PINs.

Root integration: PIN login addition to ReturningUnlockScreen (existing password/fingerprint preview), challenge mandatory before PreviewAuthState.unlocked or dashboard routes when enabled; password LoginScreen same gate. Account switch/deletion clear state; ordinary logout retains account configuration for returninglogin. All callbacks mounted/once, blocked duplicate submissions, no full set activation before all3saved. Error recovery/cooldown, scrolling keyboard smallscreens, reducedmotion immediate transitions.

Backend handoff: account-scoped server settings/challenge/grants and OTP delivery, salted slow server hashes, retry/rate limits and authenticated completion required; use passkeys/TOTP as production MFA.
